# Publishing @openplacerules/mcp (NOT DONE: needs the project owner's approval for every step)

## Does the official MCP Registry need an npm package? Yes, for this server.
Checked 2026-11-22 ICT in the registry docs:
https://github.com/modelcontextprotocol/registry/tree/main/docs/modelcontextprotocol-io (quickstart.mdx, package-types.mdx, authentication.mdx).
- The registry "only hosts metadata, not artifacts". A package-based (stdio) server must first be published to a public package registry. For npm that is
  registry.npmjs.org, and `npm publish --access public` comes before `mcp-publisher publish`.
- Ownership check for npm: `package.json` must contain `"mcpName"` equal to `server.json` `name`. Here both are `org.openplacerules/mcp`.
- The only package-free route is a *remote* server (`remotes` with a public streamable-http URL). We have no hosted endpoint, so that doesn't apply yet.
- The registry is in preview; breaking changes or data resets may occur.

## Name choice
- `org.openplacerules/mcp` uses **domain auth** on openplacerules.org (HTTP well-known file or DNS TXT), so no GitHub org is needed.
  Alternative: `io.github.<user>/openplacerules`, with GitHub auth. Org namespaces then need an org Owner using a PAT or GitHub Actions.
- npm scope `@openplacerules` needs an npm **organization** named `openplacerules` (free for public packages). On 2026-11-22,
  `https://registry.npmjs.org/@openplacerules%2fmcp`, `/openplacerules` and `/openplacerules-mcp` all returned 404 (unused).
  Org availability can only be confirmed when creating it. Fallback without an org: rename to unscoped `openplacerules-mcp`
  (update `name` in scripts/build_mcp_package.js and `identifier` in server.json).

## Files
- `server.json`: hand-written; validates against https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json (description ≤ 100 chars).
- Everything else is generated by `node scripts/build_mcp_package.js`: package.json with `mcpName`, `bin: openplacerules-mcp`, mcp-server.js, lib/,
  data snapshot and licences.
- `tests/package.test.js` checks that the names and versions match and that the packed server answers over stdio.
- `npm pack --dry-run` gives 14 files, about 171 kB.

## Steps (after approval)
1. `node scripts/build_mcp_package.js && cd packages/mcp && npm pack --dry-run`
2. npm account (2FA on) → create org `openplacerules` → `npm login` → `npm publish --access public`
3. Site live at openplacerules.org (needed for domain auth of `org.openplacerules/mcp`; see docs/custom-domain.md). Generate an Ed25519 key that the project owner keeps (`openssl genpkey -algorithm Ed25519 -out key.pem`), then publish
   `/.well-known/mcp-registry-auth` = `v=MCPv1; k=ed25519; p=<base64 public key>`.
4. Install `mcp-publisher` (a release binary or brew), run `mcp-publisher login http --domain openplacerules.org` (private key via env), then `mcp-publisher publish` from packages/mcp.
5. Check: `curl "https://registry.modelcontextprotocol.io/v0/servers?search=org.openplacerules/mcp"`.
On each new data/code release, bump `version` in the root package.json (it flows into the package) and in server.json, both places.
